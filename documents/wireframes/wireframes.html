Game Play

UI Toolkit製のHUD（透明背景・最前面）と、uGUI製のパズル本体（グリッド＋パレット）の2層構造。

HUD（UI Toolkit） パズル本体（uGUI・データ依存） タップ領域

グリッド寸法はステージごとに実行時計算（右パネル参照）

要素と挙動

HUD top
戻る矢印 + ステージ名。背景帯なし（透過）。（旧: バー背景 rgba(0,0,0,.5)、2026-07-11に削除）
タイマー
headerH直下の予約帯に固定。残量比率で緑→黄→赤に遷移。
メイングリッド
セルサイズ = min(幅/cols, 高さ×0.8/rows, 90px)（旧上限45px）。予約帯（header+timer）の下から常に開始。
ジェム移動
選択中グループは同じ目標色のマスにしか移動できない。旧実装は目標色のない自由マスへ色を問わず移動できる抜け穴があった（2026-07-11修正、GridManager.FindContiguousEmpty()）。
パレット
一時退避エリア。既定2段。2段目はロックされ、行全体タップで Unlock ダイアログ（旧: 専用の小ボタンのみ）。
HUD bottom
Undo / Hint / Reset の3ボタン。背景帯なし（透過）。（旧: バー背景 rgba(0,0,0,.5)、2026-07-11に削除）
決定事項：タイマーは headerH と同じ「予約帯」方式に変更（旧: top:480px 絶対値）。availH = canvasH − headerH − timerH − bottomH とし、グリッドは構造的にこの帯の下からしか始まらない。詳細は screen-specification.md §6-1。
決定事項：マス/ジェムが小さく見える主因は固定上限 maxMainCellSize=45px だった。13×13（Stage_001実データ）では幅から約81px出せるのに45pxへ潰されていたため、上限を 90px（パレットは100px）に引き上げる。高密度ステージ（24列等）は幅制約が先に効くため副作用なし。上のフレームは新しい見え方（13×13, 6%マージン）で表示中。

列数の偶数・奇数センタリング確認

ランタイムのセンタリング計算は列数の偶奇を区別しない。奇数なら中央に1本の軸、偶数なら中央が2列の境界になるだけで、どちらも中心線に対して対称になる。

偶数: 8列 （中央は2列の境界）
奇数: 13列 （中央に軸マス1つ）

SortGems / Visual Design Spec

Cozy Lo-Fi Pixel Palette

カラージェム系パズルゲーム 色指定シート v1.0 を元にしたビジュアル設計書。90年代のゲームセンターやカセットテープのノスタルジーを、Lo-fiで優しいパステルカラーとドット表現で再構築した世界観。

参照元: ユーザー提供リファレンス画像「COZY LO-FI PIXEL PALETTE v1.0」（2026-07-11）
関連: documents/screen-specification.md（画面仕様）
本書はレイアウトではなく配色・素材・トーンを定義するドキュメント。
現状実装との差分メモ: 現行の GemColorPalette.cs は Red/Blue/Green/Yellow/Purple/Orange/Cyan/Pink/White/Black/Brown/LightBlue の12色構成で、彩度の高いビビッドな配色。本シートが提案する8色パステル配色（Pink/Coral/Orange/Lemon/Mint/Sky/Lavender/Purple）とは系統が異なる。同様に Common.uss の --color-bg: rgb(24,24,32) 等のUIトークンも、本シートの Night Navy(#282845)を基準にしたウォームなパレットへは未移行。本書は「目標とするアートディレクション」を定義するものであり、実装への適用は別途スコープとして計画する。

03Art Direction

  • 太めのアウトライン — オブジェクトは幅感のある濃い色で輪郭を取る。
  • 丸みのあるピクセル — 角を切り落とし、かわいらしい印象にする。
  • 発光は抑えめ — 強いネオンやグローは使わず、柔らかなグローで演出。
  • 温かみのある陰影 — 影は茶やブラウンを基調に、画面全体に統一感を出す。
  • 長時間遊べる画面設計 — コントラストを抑え、目に優しいレイアウトにする。

04Gem Design Guide

形状ルール

  • 外枠は八角形。枠線は色に依存しない固定の「Frame」トーン（§02）を使い、宝石が枠にセットされたような見た目にする。
  • 中央に一回り小さい正方形（テーブル面）を内側に配置。辺は外枠と同じく水平・垂直のまま（45°回転はさせない）。正方形の4つの頂点それぞれから、隣接する八角形の頂点2つへ向けてカットが伸び、外枠との間が「辺ごとの台形4面＋角の三角形4面」に分割される（テーブル1面＋台形4面＋三角形4面＝計9面）。
  • 面ごとの明暗だけで傾いて見えるようにする。左上（上辺・左辺の台形＋左上の三角形）を最も明るく、右下（右辺・下辺の台形＋右下の三角形）を最も暗く、テーブル面と残り2つの三角形は中間トーンにする。
  • 左上の明るい面の内側に小さな白いスパークルを1点重ね、宝石らしい反射のキラつきを足す。

ジェムサイズ比率（例）

サイズは8の倍数で設計する。八角形の角の落とし幅・ファセット構成比はサイズによらず一定。

09Do & Don't

DO（推奨）

  • やさしいパステルカラーを使う
  • コントラストは強くしすぎない
  • 統一感のある影と光を使う
  • ノスタルジックな要素を取り入れる
  • 見やすさを最優先にする

DON'T（避ける）

  • 強いネオンや高彩度の原色
  • 真っ黒の影や輪郭
  • 過剰な発光・フラッシュ
  • 情報量の多すぎる画面
  • 世界観に合わないモチーフ

10Cell / Socket States （参照画像には無い追加項目）

パズルグリッド1マス（GemCellView.cs実装で確認・2026-07-11）の状態別デザイン。マスの色味はジェムと同じ配色トークン（§01）を使い回す。マスの背景色は正解・不一致・空のどの状態でも常に目標色のまま変化しない（変えてしまうと「何色を置けばよいか」が分からなくなりパズルとして成立しない）。状態によって変わるのは、ジェムがハマる位置のくぼみ（ソケット）の表示有無と、ジェム自体の色・影の有無だけ。
