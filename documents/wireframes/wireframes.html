03 — Flow

Game Play

UI Toolkit製のHUD（透明背景・最前面）と、uGUI製のパズル本体（グリッド＋パレット）の2層構造。

HUD（UI Toolkit） パズル本体（uGUI・データ依存） タップ領域

グリッド寸法はステージごとに実行時計算（右パネル参照）

要素と挙動

HUD top
戻る矢印 + ステージ名。バー背景 rgba(0,0,0,.5)。
タイマー
headerH直下の予約帯に固定。残量比率で緑→黄→赤に遷移。
メイングリッド
セルサイズ = min(幅/cols, 高さ×0.8/rows, 90px)（旧上限45px）。予約帯（header+timer）の下から常に開始。
パレット
一時退避エリア。既定2段。2段目はロックされ、行全体タップで Unlock ダイアログ（旧: 専用の小ボタンのみ）。
HUD bottom
Undo / Hint / Reset の3ボタン。バー背景 rgba(0,0,0,.5)。
決定事項：タイマーは headerH と同じ「予約帯」方式に変更（旧: top:480px 絶対値）。availH = canvasH − headerH − timerH − bottomH とし、グリッドは構造的にこの帯の下からしか始まらない。詳細は screen-specification.md §6-1。
決定事項：マス/ジェムが小さく見える主因は固定上限 maxMainCellSize=45px だった。13×13（Stage_001実データ）では幅から約81px出せるのに45pxへ潰されていたため、上限を 90px（パレットは100px）に引き上げる。高密度ステージ（24列等）は幅制約が先に効くため副作用なし。上のフレームは新しい見え方（13×13, 6%マージン）で表示中。

列数の偶数・奇数センタリング確認

ランタイムのセンタリング計算は列数の偶奇を区別しない。奇数なら中央に1本の軸、偶数なら中央が2列の境界になるだけで、どちらも中心線に対して対称になる。

偶数: 8列 （中央は2列の境界）
奇数: 13列 （中央に軸マス1つ）
03a — Overlay on Game Play

Cleared

全マスの色が一致すると表示。背景スクリムの上に中央固定パネル。

タイトル色 success accent / 72px

要素と挙動

タイトル
“CLEARED!” --fs-display 72px、accentゴールド。
ボタン1
Next Stage（btn-lg）。次ステージがあれば広告確率表示 → ロード、無ければ Stage Select へ。
ボタン2/3
Replay（ステージ再挑戦） / Back（Stage Select）。
クリア演出として、対象ステージの各マスに遅延つきエフェクトが順番に再生される（(r+c)*0.03s ずらし）。ワイヤーフレームには不可視。

03c — Overlay on Game Play

Unlock Row 2

パレット2段目（ロック中）をタップすると表示。ゲームは一時停止する。

パネル幅 min-width 520px（1080基準）

要素と挙動

タイトル
“Unlock Row 2” 40px。
説明文
「アイテム使用または広告視聴で2段目パレットを解放」。
ボタン1
Use Item（アイテム在庫チェック未実装 = TODO）。
ボタン2/3
Watch Ad / Back（キャンセルで再開）。
検討ポイント：「Use Item」の在庫UIが存在しない。所持数0でもボタンは常に活性のまま押せてしまう現状。
凡例の読み方： 実線＝毎回同じ静的UIシェル。破線＝ステージデータ／プレイ状況によって内容や個数が変わる領域。数値はすべて現行実装のソースコードから抽出した参考値（1080×1920基準）で、最終デザインでの確定値ではありません。詳細は documents/screen-specification.md を参照。
